### 1.2 解决的问题

校园信息系统的登录入口是账号盗用、暴力破解、账号共享的高发点，但登录行为通常只留在各业务系统自己的日志里，缺少统一监测。本平台：

1. 提供统一日志接收入口，让被监控系统把登录事件上报进来（`POST /api/logs`）；
2. 按固定规则自动识别异常登录并生成分级告警；
3. 通过邮件与实时推送把告警送达管理员；
4. 提供后台界面供管理员查询日志、查看趋势、处理告警。

### 1.3 使用场景

| 场景 | 参与方 | 触发链路 |
|---|---|---|
| 日常监控 | 管理员 | 打开仪表盘看今日登录量与告警趋势（`GET /api/stats`、`GET /api/stats/alerts`） |
| 异常发现 | 被监控系统 + 平台 | 上报日志 → Celery 实时检测 → 生成告警 → SSE 推送 + 邮件 |
| 事后审计 | 管理员 | 按用户名/IP/状态/时间范围筛选登录日志（`GET /api/logs`） |
| 告警处置 | 管理员 | 确认/解决告警（`PUT /api/alerts/{id}`）、清空已处理告警（`DELETE /api/alerts?scope=processed`） |
| 演示与压测 | 开发者 | 用 `monitored-app`（Flask 仿真器）制造频率/设备异常样本 |

## 2. 项目目标

以下目标来自项目自带文档的显式声明（**源码事实：文档声明**，不是代码推导）：

- 接收并留存校园系统登录日志（`docs/DESIGN.md:12-16`）。
- 通过可配置阈值的规则检测异常登录：频率异常、设备异常（`docs/DESIGN.md:77-88`）。
- 生成分级告警（`low/medium/high`）并提供处理流转（`pending → acknowledged → resolved`）。
- 提供可视化后台（日志列表、告警列表、趋势图表、系统设置）。
- 以 8 周迭代交付：第 1–8 周计划及完成状态见 `docs/DESIGN.md:45-56`。

**能力边界（源码事实）**：

- 无多租户、无被监控系统侧 SDK、无日志加密存储、无告警规则可视化配置界面（`docs/DESIGN.md:59` 将其列为后续扩展）。
- 无 RBAC：`User.role` 字段存在但代码中除默认值 `"admin"`（`models/user.py:19`）与邮件收件人筛选（`tasks/email.py:22`）外**没有任何权限判断分支**。

## 3. 核心功能

| # | 功能 | 实现位置 | 说明 |
|---|---|---|---|
| F1 | 管理员认证（JWT） | `api/auth.py:14-45`、`core/security.py` | 登录签发 HS256 JWT（默认 1440 分钟）；注册需已登录管理员 |
| F2 | 登录日志接收 | `api/logs.py:15-22`、`services/logs.py:49-60` | `X-API-Key` 鉴权，落库后触发异步检测 |
| F3 | 登录日志查询 | `api/logs.py:25-47` | 支持用户名模糊、IP 精确、状态、时间范围、分页 |
| F4 | 频率异常检测 | `services/detection.py:14-80` | 同一用户名 5 分钟内 `≥10` 次 → `medium`（≤30）/ `high`（>30） |
| F5 | 设备异常检测 | `services/detection.py:83-149` | 同一用户名 1 小时内不同 `(user_agent, ip_address)` 组合 `≥2` → `medium`（=2）/ `high`（>2） |
| F6 | 告警去重 | `services/detection.py:152-179` | 24 小时内同 `username` + 同 `alert_type` 且 `status=pending` 时不再建新告警 |
| F7 | 告警查询与状态流转 | `api/alerts.py:16-80` | 列表/详情/状态更新（`resolved` 时写 `resolved_at`） |
| F8 | 实时推送（SSE） | `api/notifications.py:31-61` + `tasks/detection.py:16-27` | 检测任务 `PUBLISH` 到 Redis 频道 `alerts`，SSE 端点订阅并下发 |
| F9 | 邮件告警 | `tasks/email.py:59-93` | 异步发送给所有 `role=admin` 且 `is_active=True` 的管理员；未配置 SMTP 时跳过 |
| F10 | 邮件配置诊断 | `api/settings.py:19-77` | 查看配置状态、发送测试邮件（含 SMTP 认证失败/连接失败分类提示） |
| F11 | 定时增量检测 | `tasks/__init__.py:18-23`、`tasks/detection.py:94-143` | Celery Beat 每 3600 秒执行一次，游标存 Redis |
| F12 | 统计聚合 | `api/stats.py:16-111` | 今日登录、待处理告警、活跃用户、登录趋势、告警趋势/类型分布/级别分布 |
| F13 | 数据清理 | `api/logs.py:50-58`、`api/alerts.py:83-96` | 清空全部日志；清空全部/已处理告警（**无软删除、无审计日志**） |
| F14 | 双管理端 | `frontend/`、`flutter_app/` | 功能等价的 Vue 后台（浏览器）与 Flutter 客户端（Windows/Web） |
| F15 | 被监控系统仿真 | `monitored-app/` | Flask 登录页 + `/api/simulate` 生成频率/设备异常样本 |

完整状态机与调用链见 `04-核心流程与数据流.md`。

### 4.5 关键选型说明（源码支撑）

- **Redis 同时承担三种角色**：Celery broker + result backend（`tasks/__init__.py:6-7`）、告警实时频道 pub/sub（`tasks/detection.py:20`、`api/notifications.py:42`）、增量检测游标存储（`tasks/detection.py:33,47`）。这一「一号多用」是后续多个问题的根源，详见 `11-性能分析.md` 与 `14-评估与改进.md`。
- **MySQL 8.0 而非 SQLite**：生产与开发统一走 MySQL（`docker-compose.yml:5`），仅在单元测试中使用临时 SQLite（`tests/conftest.py:12-24`）。
- **Celery 而非 FastAPI BackgroundTasks**：需要 Beat 定时增量检测与独立 worker 扩容（`docker-compose.yml:66-112`）。
- **双管理端**：Vue 与 Flutter 覆盖同一批 API（端点级对照见 `05-API文档.md` §13.4）；Flutter 目录尚未纳入版本控制，属**高风险状态**（见 `14-评估与改进.md`）。
