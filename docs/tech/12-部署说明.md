## 22. 部署说明

### 22.1 环境要求

| 项 | 要求 | 依据 |
|---|---|---|
| 操作系统 | 源码中未做平台限定；Docker 方式与 OS 无关；本地开发脚本含 Windows/PowerShell 示例（`scripts/seed_logs.py:5`） | — |
| 容器运行时 | Docker + Docker Compose（`docker-compose.yml:1` 使用顶层 `name:` 字段，建议 Compose v2） | `docker-compose.yml:1` |
| 后端运行时（本地开发） | Python 3.11+（Black 配置 `target-version = py311`；容器用 3.12）；本次实测环境为 **Python 3.13.13**，可运行 | `pyproject.toml:3`、`Dockerfile:1` |
| Node.js（本地前端） | 容器使用 `node:20-alpine` | `frontend/Dockerfile:1` |
| Flutter SDK（客户端） | `sdk: ^3.13.0`；`pubspec.lock` 声明 `flutter >=3.44.0`（📄） | `flutter_app/pubspec.yaml:7` |
| MySQL | 8.0（镜像） | `docker-compose.yml:5` |
| Redis | 7（`redis:7-alpine`） | `docker-compose.yml:25` |
| 其他 | 无单独安装要求 | — |

### 22.2 Docker Compose 全栈部署

```bash
cd E:/实习
docker-compose up -d            # 启动全部 6 个服务
docker-compose ps               # 查看状态
docker-compose logs -f backend  # 跟踪后端日志
docker-compose down             # 停止并删除容器（保留卷）
docker-compose down -v          # 连同数据卷一起删除（会清空数据库）
```

**服务清单**（`docker-compose.yml`）：

| 服务 | 镜像/构建 | 容器名 | 主机端口 | 依赖 | 命令 |
|---|---|---|---|---|---|
| `mysql` | `mysql:8.0` | `campus_mysql` | **8881** → 3306 | — | 默认 |
| `redis` | `redis:7-alpine` | `campus_redis` | **8880** → 6379 | — | 默认 |
| `backend` | `build: ./backend` | `campus_backend` | **8000** → 8000 | mysql/redis healthy | `entrypoint: docker-entrypoint.sh` |
| `celery-worker` | `build: ./backend` | `campus_celery_worker` | 无 | mysql/redis healthy | `celery -A app.tasks worker --loglevel=info` |
| `celery-beat` | `build: ./backend` | `campus_celery_beat` | 无 | mysql/redis healthy | `celery -A app.tasks beat --loglevel=info` |
| `frontend` | `build: ./frontend` | `campus_frontend` | **8882** → 80 | backend | Nginx 默认 |

**卷（volumes）**：

| 卷 | 挂载点 | 说明 |
|---|---|---|
| `mysql_data`（命名卷） | `/var/lib/mysql` | 数据库持久化 |
| `redis_data`（命名卷） | `/data` | Redis 持久化 |
| `./backend/alembic/versions`（bind） | `/app/alembic/versions` | **backend / celery-worker / celery-beat 三个服务均挂载**（`docker-compose.yml:60-61,85-86,110-111`），便于在宿主机新增迁移后被容器立即看到 |

**网络**：自定义 bridge `campus-net`（`docker-compose.yml:130-132`），所有服务加入；容器间通过服务名互访（`mysql:3306`、`redis:6379`、`backend:8000`）。

**健康检查**：仅 `mysql`（`mysqladmin ping`）与 `redis`（`redis-cli ping`）配置了 healthcheck（10s 间隔 / 5s 超时 / 5 次重试）；**backend、frontend、celery 无 healthcheck**。

**重启策略**：**源码中未发现**（无 `restart:` 配置）⇒ 宿主机重启后容器不会自动拉起。

### 22.3 容器启动行为

`backend/docker-entrypoint.sh` 依次执行：

1. 循环探测 MySQL 可用（`pymysql.connect` 硬编码主机/账号/库名，`:5`）；
2. `alembic upgrade head`（`:11`）—— 自动建表/升级；
3. `python scripts/seed.py`（`:14`）—— 幂等创建默认管理员 `admin` / `admin123`（已存在则跳过，`scripts/seed.py:21-24`）；
4. `exec uvicorn app.main:app --host 0.0.0.0 --port 8000`（`:17`）。

`celery-worker` / `celery-beat` 由 `command` 直接覆盖，**不经过 entrypoint**，因此**不执行迁移与 seed**；它们依赖 `backend` 先完成建表（compose 只声明了 `depends_on: mysql/redis healthy`，**未声明依赖 backend**，存在首次启动竞态：worker 可能在表建好前开始消费任务）。

**首次启动后的访问入口**：

| 入口 | 地址 | 说明 |
|---|---|---|
| 前端（推荐） | `http://localhost:8882` | Nginx 托管静态资源并把 `/api` 反代到 `backend:8000` |
| 后端 API | `http://localhost:8000` | 容器后端 |
| API 文档 | `http://localhost:8000/docs` | Swagger UI |
| MySQL | `localhost:8881` | 客户端连接用 |
| Redis | `localhost:8880` | 客户端连接用 |

登录账号：`admin` / `admin123`（`scripts/seed.py:29`；**生产部署必须立即修改**）。

### 22.4 前端镜像构建细节

`frontend/Dockerfile`（多阶段）：

```text
stage1: node:20-alpine
  npm config set registry https://registry.npmmirror.com
  COPY package*.json → npm install
  COPY . . → npm run build          # 产出 /app/dist
stage2: nginx:stable-alpine
  COPY nginx.conf → /etc/nginx/conf.d/default.conf
  COPY --from=build /app/dist → /usr/share/nginx/html
```

- 使用 `npm install`（**不是 `npm ci`**），未严格按 lockfile 的确定性安装语义执行。
- `frontend/.dockerignore` 存在（📄），用于排除 `node_modules`/`dist` 等。
- 宿主机上的 `frontend/dist/` 与本镜像无关：镜像内从源码重新构建（`AGENTS.md` 亦强调此点）。改动前端后需 `docker-compose up -d --build frontend` 才会在 8882 生效。

### 22.5 本地开发部署（不用容器跑应用）

```bash
# 1) 只起基础设施（注意：直接用 up -d 会拉起全部 6 个服务，占用 8000/8882）
docker-compose up -d mysql redis

# 2) 后端
cd backend
pip install -r requirements.txt
alembic upgrade head
python scripts/seed.py
uvicorn app.main:app --reload --port 8001

# 3) Celery（可选，需 Redis）
celery -A app.tasks worker --loglevel=info
celery -A app.tasks beat --loglevel=info

# 4) 前端
cd ../frontend
npm install
npm run dev        # http://localhost:5173（注意 dev proxy 默认指向 8000）
```

⚠️ 本地开发两个已知坑：

1. **端口不一致**：`frontend/vite.config.js:10,16` 代理到 `8000`（容器后端端口），而本地后端按 README 跑在 `8001`。二选一：把本地后端改为 `--port 8000`，或把 vite 代理目标改为 `8001`（见 `13-开发指南.md` FAQ-03）。
2. **`.env` 的工作目录依赖**：必须在 `backend/` 目录下启动进程，否则 `pydantic-settings` 找不到 `.env`，会静默使用代码默认值（例如 `DATABASE_URL` 指向 `localhost:3306` 而非 `8881`）。

### 22.6 生产部署

> **当前源码未发现完整的生产部署方案。**

源码内**不存在**以下生产部署要素（均为实测核查）：

| 缺失项 | 说明 |
|---|---|
| 生产编排文件 | 无 `docker-compose.prod.yml`、无 K8s manifest、无 Helm chart |
| TLS/HTTPS 终止 | `nginx.conf` 只监听 80，无证书配置、无 443、无 HSTS |
| 反向代理与域名 | `server_name _`，未配置域名与外部 LB |
| 数据库高可用/备份 | 单实例 MySQL，无主从、无备份脚本、无 `mysqldump` 计划任务 |
| 密钥管理 | 无 Vault/Secrets Manager；凭据在 compose 环境变量与本地 `.env` |
| 资源限制 | 无 `deploy.resources`/`mem_limit`/`cpus` |
| 重启策略 | 无 `restart:` |
| 日志采集 | 无 ELK/Loki 等；依赖容器 stdout |
| 监控告警 | 无 Prometheus/Grafana/健康上报（仅有 `/api/health` 端点可供外部探活） |
| CI/CD | 无任何流水线配置（实测 `.github/` 等均不存在） |
| 迁移执行策略 | 依赖 backend 容器 entrypoint 自动执行（多副本部署时会并发执行迁移，存在风险） |

**若要上生产，最低限度需要**：

1. 收敛 CORS 白名单（`main.py:21-27`）；
2. 强制替换 `SECRET_KEY` / `API_KEY` / 数据库口令 / 关闭示例管理员（`core/config.py:13,16`、`scripts/seed.py:29`）；
3. 加 TLS 终止（Nginx 443 + 证书）与访问日志脱敏（SSE 路径 query 含 token）；
4. 为所有服务配置 `restart: unless-stopped` 与资源限制；
5. 关闭 `monitored-app` 或仅在内网运行（其 `debug=True`，`app.py:139`）；
6. 建立数据库备份与日志归档策略；
7. 修复 PERF-00（Redis 阻塞上报）——否则 Redis 抖动的后果是平台整体不可用。

## 23. 开发环境搭建

### 23.1 从零开始

```text
1. 安装环境      Docker Desktop（含 Compose v2）；本地后端需 Python 3.11+；前端需 Node.js 20；客户端需 Flutter SDK 3.x
2. 获取源码      git clone <repo> && cd 实习  （当前工作副本分支为 dev）
3. 安装依赖      后端 pip install -r backend/requirements.txt（建议虚拟环境）
                 前端 cd frontend && npm install
                 仿真器 cd monitored-app && pip install -r requirements.txt
4. 配置环境变量  cp backend/.env.example backend/.env，按需填写；至少确认 DATABASE_URL 端口为 8881、REDIS_URL 为 8880
                 注意：.env.example 的 ACCESS_TOKEN_EXPIRE_MINUTES=30 与代码默认 1440 不同，按需选择
5. 初始化数据库  docker-compose up -d mysql redis
                 cd backend && alembic upgrade head && python scripts/seed.py
6. 启动项目      backend: uvicorn app.main:app --reload --port 8001
                 frontend: npm run dev（先把 vite 代理目标与后端端口对齐）
                 celery: celery -A app.tasks worker --loglevel=info（可选）+ beat（可选）
7. 运行测试      cd backend && pytest tests/ -v
                 ⚠️ 无 Redis 时 test_detection.py 会挂死，见 09-测试体系.md §19.3
```

### 23.2 环境变量最小集

| 变量 | 本地开发建议值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `mysql+pymysql://campus_user:campus123@localhost:8881/campus_monitor` | 主机端口是 **8881** |
| `REDIS_URL` | `redis://localhost:8880/0` | 主机端口是 **8880**（非 6379） |
| `SECRET_KEY` | 任意随机串（本地） | 生产必须强随机 |
| `API_KEY` | 与上报方一致即可 | 默认 `dev-api-key-change-in-production` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 1440 | 模板里是 30 |
| `EMAIL_*` | 留空 → 邮件功能自动跳过 | 需要时填真实 SMTP（163 用 465 + SSL） |
