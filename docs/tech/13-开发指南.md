## 24. 开发指南

### 24.1 分层约定（当前代码实际遵循的规则）

| 层 | 目录 | 应该放什么 | 不应放什么 |
|---|---|---|---|
| 路由 | `app/api/` | 路由声明、依赖注入、HTTP 状态码、参数解析 | 复杂业务逻辑（`alerts.py`/`stats.py` 目前是反例，逻辑直接写在 router 中） |
| 校验 | `app/schemas/` | Pydantic 模型、字段约束（`pattern`/`Literal`/`Field` 边界） | 业务规则 |
| 业务 | `app/services/` | 检测规则、认证、查询构造、事务提交 | FastAPI 相关导入（用自定义异常代替 `HTTPException`，参见 `services/auth.py:9-11`） |
| 数据 | `app/models/` | ORM 字段与索引声明 | 业务逻辑 |
| 异步 | `app/tasks/` | Celery 任务；可复用 `services` 的能力 | 直接依赖请求上下文 |

**事务约定**：当前是「谁写库谁提交」（`services/auth.py:40`、`services/logs.py:53`、`services/detection.py:77,146`），API 层无法把多次 service 调用包进一个事务。若新增需要原子性的多步写入，请在 service 内新增一个组合函数并只提交一次。

### 24.2 新增一个 API 端点的固定步骤

```text
1. 在 app/schemas/ 定义请求/响应模型
   └─ 响应模型必须加 model_config = ConfigDict(from_attributes=True)（否则从 ORM 反序列化报错）
2. 在 app/services/ 实现业务函数（若逻辑简单且与既有风格一致，也可直接写在 router——但要接受与 alerts/stats 一样的一致性代价）
3. 在 app/api/xxx.py 定义路由并挂鉴权依赖：
   └─ 管理端接口用 Depends(get_current_active_user)
   └─ 机器上报接口用 Depends(verify_api_key)
4. 若是新文件，必须在 app/main.py 手动 import 并 app.include_router(..., prefix=settings.API_V1_PREFIX, tags=[...])
   ⚠️ 本项目没有自动路由扫描，漏写这一步接口不会生效
5. 补测试（backend/tests/），至少覆盖：正常路径、鉴权失败、参数非法
6. 更新文档：docs/tech/05-API文档.md 与 docs/tech/06-数据库设计.md（若涉及模型）
```

### 24.3 新增数据模型 / 字段的固定步骤

```text
1. 编辑 app/models/xxx.py
2. ⚠️ 在 app/models/__init__.py 显式 import 新模型
   └─ 否则 alembic autogenerate 与 Base.metadata 都会漏掉它（当前已登记：User、LoginLog、Alert）
3. cd backend && alembic revision --autogenerate -m "描述"
4. 人工审阅生成的迁移，特别注意：
   └─ 加 NOT NULL 列要给 server_default（历史迁移 2e7a3f8b1c4d:23 就漏了，见 06-数据库设计.md §14.2）
   └─ 外键要显式声明 ondelete（历史迁移未声明，导致删除父表行会被 RESTRICT 拦住）
5. alembic upgrade head
   ⚠️ 不要用 Base.metadata.create_all() 建表，本项目统一走迁移
6. 若字段进入响应，同步更新 schemas 与文档
```

### 24.4 新增前端页面（Vue）

```text
1. src/views/Xxx.vue（参考 Alerts.vue 的结构：SectionCard + FilterBar + DataTable + TablePagination）
2. src/api/xxx.js 封装请求（参考 logs.js：直接复用 src/api/index.js 的 axios 实例）
3. src/router/index.js 在 MainLayout 的 children 下加路由（带 meta.requiresAuth）
4. 若需要未读角标/实时提示，改 stores/notification.js
5. 不要直接写死后端地址：统一走 api 模块（Dashboard.vue 目前有两处绕过 api 模块直接请求的反例）
```

### 24.5 新增客户端页面（Flutter）

```text
1. lib/models/ 加数据模型（fromJson 字段名必须与后端 AlertResponse/LoginLogResponse 一致）
2. lib/services/ 加服务类，统一经 lib/services/api_client.dart 发请求
3. lib/pages/ 加页面，加入 lib/pages/shell_page.dart 的 _pages 列表与导航项
4. 401 处理统一走 lib/utils/api_guard.dart
5. ⚠️ SSE 事件体是精简格式（{alert_id,type,severity,username}），不要直接当 AlertResponse 解析（现有缺陷见 04-核心流程与数据流.md §9.8）
```

### 24.6 枚举与词表（裸字符串，写错不报错）

| 字段 | 合法取值 | 定义/校验位置 |
|---|---|---|
| `Alert.alert_type` | `frequency`、`device` | 无约束；Flutter 侧常量见 `flutter_app/lib/models/alert.dart:69-78` |
| `Alert.severity` | `low`、`medium`、`high` | 无约束；产生值见 `services/detection.py:55-60,124-129` |
| `Alert.status` | `pending`、`acknowledged`、`resolved` | 无约束；`pending` 会阻塞新告警（去重） |
| `LoginLog.login_status` | 现状 **`success` / `failure`** | 查询参数正则 `schemas/logs_query.py:13`；**`monitored-app` 用了 `failed`，是唯一离群值** |
| `User.role` | 现仅 `admin` | 无权限判断分支 |

**建议**：新增代码把这些值集中为 Python 常量（或 `Literal`/`Enum`），至少在新写的 schema 中使用 `Literal`，避免继续扩大裸字符串面。

### 24.7 明确的「不要这样做」

| 禁止 | 原因 |
|---|---|
| 用 `Base.metadata.create_all()` 建表 | 绕过迁移，导致库结构与 `alembic/versions` 不一致 |
| 忘记在 `models/__init__.py` 注册新模型 | Alembic autogenerate 漏表 |
| 新增模型忘了在 `main.py` 注册路由 | 无自动扫描，接口静默不生效 |
| 调整 `vite.config.js` 中 `/api/notifications` 与 `/api` 的顺序 | SSE 会被普通代理规则吞掉（`ws:false` + `Connection: keep-alive` 也是必需的） |
| 把 `GET /api/notifications/stream` 的 token 改回 `Authorization` 头 | 浏览器 `EventSource` 不支持自定义头，会导致实时推送失效 |
| 直接 `import app.core.redis` 的 `redis_client` | 那是死代码；现有 Redis 客户端在 `tasks/detection.py` 自建 |
| 在 service 层 import FastAPI 的 `HTTPException` | 会破坏分层；用自定义异常在 API 层转换 |
| 对 `alerts.log_id` 相关表做 `delete()` 而不考虑外键 | 会触发 FK RESTRICT 错误（见 06-数据库设计.md §14.7） |
| 在日志/响应中输出凭据、token、密钥 | 平台自身即安全审计系统 |

### 24.8 提交与代码风格

| 项 | 现状 |
|---|---|
| 格式化 | 后端 `black .`（line-length=100，排除 `alembic/`）；前端无格式化工具（**建议引入 Prettier**） |
| Lint | 后端 `flake8` 未安装且无配置；前端 `.eslintrc.cjs` 无效（无依赖、无脚本）——**当前实际没有可用的 lint 管线** |
| 行尾 | 无 `.gitattributes`；本机 `core.autocrlf=true` 会产生整文件行尾 diff。建议：`git -c core.autocrlf=false add ... && git -c core.autocrlf=false commit ...`（`AGENTS.md` 亦有此提示） |
| 提交信息 | 历史混用类型（`feat:`/`fix:`/`docs:`/`test:`）与无意义信息（如 `1`） |
| 版本控制盲区 | **`flutter_app/` 未被 git 跟踪**（实测 `git status` = `?? flutter_app/`）——务必尽快纳入，否则该目录只有单点副本 |

## 25. Debug 指南

### 25.1 分层排查思路

```text
1. 前端/客户端现象 → 浏览器 F12 Network（看请求是否发出、状态码、响应体）
2. 到达后端了吗？ → docker-compose logs -f backend / uvicorn 控制台 access log
3. 鉴权问题？     → 401 还是 422：422 多为缺 X-API-Key 头或字段类型不符
4. 业务问题？     → 直接在容器内跑 python，调用 services 层函数验证
5. 异步问题？     → docker-compose logs -f celery-worker，并注意「任务失败会返回字符串而不报错」
6. 推送问题？     → redis-cli 订阅频道看是否有消息；再 curl SSE 端点看是否有 data 帧
7. 数据问题？     → 直接查 MySQL（端口 8881）核对 login_logs/alerts
```

### 25.2 症状 → 根因速查表

| 症状 | 优先怀疑 | 定位方式 |
|---|---|---|
| 上报接口**卡住不返回**（不报错，浏览器一直转圈） | Redis 不可达 ⇒ Celery 结果后端无限重试（PERF-00） | `docker-compose ps redis`；`redis-cli -p 8880 ping`；看后端线程栈 |
| 上报返回 401 | `X-API-Key` 与后端 `settings.API_KEY` 不一致（尤其 `monitored-app` 默认值与代码默认值不同） | 打印 `settings.API_KEY` 与调用方实际发送值比对（`core/deps.py:64`） |
| 上报返回 422 | 缺 `X-API-Key` 头；或 `login_time`/`login_status` 等必填字段缺失或类型错误 | `core/deps.py:62`（Header 为必填）+ `schemas/login_log.py:6-12` |
| 日志列表按「失败」筛不出东西 | 上报方写了 `failed`，而查询只接受 `failure`（会得到 422） | 查库：`SELECT DISTINCT login_status FROM login_logs` |
| 有日志但**不产生告警** | ① Celery worker 未运行；② Redis 不可达；③ 去重把新告警挡住了（24h 内已有同用户同类型 pending 告警）；④ 未达阈值 | ① `docker-compose ps`；③ 查 `SELECT * FROM alerts WHERE username=? AND status='pending'`；④ 手动跑 `python scripts/detection_smoke.py` |
| 告警有了但**前端角标/提示不动** | SSE 未连接；或客户端解析字段不符（Flutter 的 Snackbar 永不显示是已知缺陷） | 浏览器 Network 看 `stream?token=` 是否 200 且有 data 帧；`redis-cli -p 8880 subscribe alerts` 手动发消息验证 |
| 仪表盘「今日登录」明显偏少 | 统计日界用 **UTC 零点**，北京时间上午 8 点前会有 8 小时偏移 | `api/stats.py:23-24`；对比 `SELECT COUNT(*) FROM login_logs WHERE login_time >= UTC 零点` |
| 趋势图有 7 天空洞 | 数据时间与统计口径不符（例：种子数据是过去 14 天、mock 数据是 7 天） | 查 `SELECT MIN(login_time), MAX(login_time) FROM login_logs` |
| `alembic upgrade head` 报错 | 迁移在非空表上加 `NOT NULL` 无默认列（历史迁移问题） | `versions/2e7a3f8b1c4d:23`；必要时手工补 `server_default` 或先清空表 |
| `DELETE /api/logs` 返回 500 | `alerts.log_id` 外键 RESTRICT 拦住删除 | 先 `DELETE /api/alerts?scope=all` 再删日志（临时绕过）；根治见 14-评估与改进.md |
| 本地起 5173 页面全空、请求 404/ECONNREFUSED | vite 代理指向 8000 而本地后端在 8001 | 改 `frontend/vite.config.js:10,16` 或把后端跑到 8000 |
| 改 `.env` 不生效 | `Settings` 在导入期实例化；或进程工作目录不是 `backend/` | 重启进程；确认 CWD |
| 8882 看到的还是旧界面 | Docker 前端镜像未重建 | `docker-compose up -d --build frontend` |
| 测试跑不动 / 卡住 | `test_detection.py` 未屏蔽 Celery 投递，无 Redis 时挂死 | 先只跑 `pytest tests/test_integration.py`；或按 09-测试体系.md 建议加全局 patch |
| Celery 任务「成功」但什么都没做 | 任务内 `try/except` 把异常转成了返回值 | 看 worker 日志中的**任务返回值**（`detection.py:88,140`），不是看是否有报错 |
| 邮件没发出去 | 未配置 SMTP（`EMAIL_USER` 为空或 host 含 `example`）会静默跳过 | `GET /api/settings/email` 看 `configured` 与 `note`；或 `POST /api/settings/email/test` 看分类错误 |

## 26. 常见问题

**Q1：这是给学生用的系统吗？**
不是。本平台用户只有管理员；学生/教师是被监控对象（`docs/DESIGN.md:21`，`README.md:5`）。

**Q2：为什么 `API_V1_PREFIX` 的值是 `/api` 而不是 `/api/v1`？**
变量命名与取值不一致是既成事实（`core/config.py:8`）。新增路由统一用 `settings.API_V1_PREFIX`，不要手写 `/api/v1`。

**Q3：为什么本地起了 5173 却打不开数据？**
`frontend/vite.config.js:10,16` 代理到 `localhost:8000`，而 README 的本地流程把后端跑在 8001。两者对齐其一即可。

**Q4：Redis 为什么是 8880 而不是 6379？**
`docker-compose.yml:28` 把容器 6379 映射到主机 8880，避免与本机其他 Redis 冲突。`REDIS_URL` 默认值已相应写为 8880（`core/config.py:11`）。

**Q5：忘了管理员密码怎么办？**
无重置接口。可直接改库（用 `core/security.py:get_password_hash` 生成哈希），或删除该用户后重跑 `python scripts/seed.py`。

**Q6：为什么 `admin123` 能登录，是不是有安全风险？**
该口令由 `scripts/seed.py:29` 硬编码生成，并在 `README.md:33` 公开。生产必须立即修改；当前无强制改密、无登录限流（见 `10-安全分析.md` SEC-07）。

**Q7：告警一直不出现，是不是检测坏了？**
先按顺序排查：worker 是否运行 → Redis 是否可达 → 是否被 24 小时去重挡住（`status='pending'` 的同类型告警会阻塞）→ 是否达到阈值（5 分钟 10 次 / 1 小时 3 个设备）。

**Q8：为什么同一用户短时间内多次异常只产生一条告警？**
去重设计如此（`services/detection.py:152-179`）：24 小时内同用户同类型只要存在 `pending` 告警就不再新建，避免告警风暴。处理（`acknowledged`/`resolved`）后才会再产生新告警。

**Q9：为什么 `PUT /api/alerts/{id}` 可以传任意状态？**
当前 `AlertUpdate.status` 是自由字符串（`schemas/alert.py:29-30`），这是待修复项，不建议继续依赖该行为。

**Q10：能不能删掉日志表数据？**
可以，但注意两点：① 会与 `alerts.log_id` 外键冲突（先清告警再清日志）；② 没有软删除与审计，删了就没了。

**Q11：前端为什么没有 lint / 测试命令？**
确实没有：`package.json` 只有 `dev`/`build`/`preview`，且无 eslint 依赖（实测）。`.eslintrc.cjs` 是遗留空壳。后端同理，`flake8` 需自行安装。

**Q12：Flutter 客户端和 Vue 后台功能一样吗？**
功能基本等价（均可完成登录、仪表盘、日志、告警、设置），Flutter 多出「后端地址可配置、期间告警卡、行详情弹窗、窄屏底部导航」等；但 Flutter 的实时告警提示存在缺陷（Snackbar 不显示），且分页能力弱于 Vue。**注意 `flutter_app/` 尚未纳入 git。**

**Q13：为什么 `docker-compose up -d` 之后 8000/8882 端口被占了？**
因为它会启动**全部 6 个服务**（含 backend 与 frontend），不只是 MySQL/Redis。只想起基础设施请用 `docker-compose up -d mysql redis`。

**Q14：`docs/UI.md` 的配色和界面为什么对不上？**
UI.md 是 v1.0（2026-07-07）规范，使用 `#111827` 中性灰系；前端在后续「全量视觉重写」后改为蓝色系（`App.vue:108` `--el-color-primary:#2563eb`）。以代码为准，UI.md 需更新。

**Q15：`CLAUDE.md` 在哪？**
**已被删除**（`git status` 显示 `D CLAUDE.md`），但 `AGENTS.md:3,210` 与 `docs/DESIGN.md:5` 仍在引用它，属死链，需修复。
