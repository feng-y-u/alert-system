### 4. 关键实现

**邮件构造**（`tasks/email.py`）：
```python
def build_alert_email(alert: Alert, recipients: List[str]) -> EmailMessage:
    msg = EmailMessage()
    msg["From"] = settings.ALERT_EMAIL_FROM
    msg["To"] = ", ".join(recipients)
    msg["Subject"] = f"[校园异常登录告警] {alert.severity.upper()} - {alert.alert_type} - 用户 {alert.username}"
    msg.set_content(
        f"检测到异常登录行为，请尽快登录平台处理。\n\n"
        f"告警ID: {alert.id}\n"
        f"告警类型: {alert.alert_type}\n"
        f"严重级别: {alert.severity}\n"
        f"用户名: {alert.username}\n"
        f"关联日志ID: {alert.log_id or '无'}\n"
        f"告警内容: {alert.alert_message}\n"
        f"创建时间: {alert.created_at}\n"
        f"状态: {alert.status}\n"
    )
    return msg
```

## 技术要点

### 选型：标准库 `smtplib`，无新依赖
邮件发送用 Python 标准库 `smtplib` + `email.message.EmailMessage`，无需在 `requirements.txt` 添加任何包。SMTP 连接使用 `starttls()` 加密，若配置了 `EMAIL_USER` / `EMAIL_PASSWORD` 则登录，否则匿名发送。

### 优雅降级：未配置不抛错
```python
def is_email_configured() -> bool:
    if not settings.EMAIL_USER:
        return False
    if "example.com" in settings.EMAIL_HOST or "example" in settings.EMAIL_USER:
        return False
    return True

@celery_app.task(bind=True)
def send_alert_email(self, alert_id: int) -> str:
    if not is_email_configured():
        logger.warning("Email not sent for alert %s: SMTP not configured.", alert_id)
        return f"Email skipped (SMTP not configured) for alert {alert_id}"
    ...
```
确保开发环境（占位 SMTP）下告警生成主流程不受影响。

### 收件人动态查询
不硬编码收件人，从数据库查所有 active 管理员邮箱，无收件人则跳过：
```python
def get_active_admin_emails(db: Session) -> List[str]:
    users = db.query(User).filter(
        User.role == "admin",
        User.is_active.is_(True),
        User.email.isnot(None),
        User.email != "",
    ).all()
    return [u.email for u in users if u.email]
```

## 遇到的问题与解决

### 1. 循环导入疑虑
**问题：** `tasks/detection.py` 新增 `from app.tasks.email import send_alert_email`，担心与 `app.tasks` 形成循环。
**验证：** 通过 `app.main` 正常加载路径测试通过（`from app.main import app` 不报错）。直接 `from app.tasks.detection import ...` 会触发预先存在的 `services.__init__` → `services.logs` → `tasks.detection` 循环，但该循环在本次改动前已存在，与邮件改动无关，且不影响 uvicorn / celery worker 正常启动。

### 2. 端到端测试需 Redis
**问题：** `test_detection.py` 跑不起来 —— `create_log` 内的 `detect_anomaly_for_log.delay()` 尝试连 Redis broker（端口 8880），当前环境无 Docker 即连不上。
**结论：** 这是 `AGENTS.md` 已记录的环境依赖（Celery 任务需 Redis 在跑），非本次改动引入。改为单独验证非 Celery 辅助函数（`is_email_configured` / `build_alert_email` / `get_active_admin_emails`）逻辑，均正确。

### 3. 邮件任务原本从未被调用
**问题：** 第四周留下的 `tasks/email.py` 只有 `send_alert_email` 函数签名（`return f"Would send email ..."`），且 `detection.py` 未引用它 —— 邮件通知实际从未接入检测流程。
**解决：** 本周重写 `email.py` 实现真实 SMTP 逻辑，并在 `detection.py` 两处告警生成点添加 `send_alert_email.delay(alert_id)`。
